# 查询页移动端通道选择与批次汇总设计

## 目标

在不改变桌面端现有通道按钮操作方式的前提下，解决手机端查询通道横向溢出的问题，并让桌面端和手机端的实时查询队列都持续显示本批次完成数量与总耗时。同时，手机端所有工作页面隐藏主标题下方的副标题，压缩首屏占用。

## 已确认范围

- 手机端查询通道改为位于“查询通道”标题右侧的下拉多选组件。
- 通道默认全选，继续使用现有自动调度逻辑和本地选择记忆。
- 桌面端保留现有横排通道按钮，不显示移动端下拉组件。
- 实时查询队列汇总在桌面端和手机端均显示。
- 手机端隐藏所有工作页面主标题下方的副标题；桌面端副标题保持不变。

## 移动端通道多选

“查询通道”区域在宽度不超过 720px 时改为单行标题栏：左侧保留标题和说明，右侧显示触发按钮“已选 N/总数 ▾”。点击按钮后，在区域内部展开深色玻璃风下拉层。

下拉层包含：

- “全选”复选项；
- 每个查询通道的复选项；
- 每个通道当前的“在线 / 待验证 / 未登录”状态；
- 内容超过可用高度时只在下拉层内部纵向滚动。

下拉层宽度受查询通道卡片限制，不产生页面级横向滚动。点击外部或按 Escape 关闭。至少保留一个通道；若取消最后一个通道，沿用现有逻辑自动恢复全选并提示。

桌面按钮与移动下拉共用 `selectedQuerySlotIds`，不维护第二份选择状态。任一视图改变选择后都重新渲染同一状态。

## 实时队列批次汇总

实时查询队列标题右侧不再显示固定的 “AUTO SCHEDULING”，改为：

`完成:10/56　耗时:0h:5m:32s`

规则：

- 总数取本批次条码总数；
- 完成数包含查询成功、查询失败和用户停止的终态条码；
- 查询进行中时，耗时从批次开始时刻持续增长；
- 查询完成或停止时冻结耗时；
- 查询结束后的汇总保留到下一批查询开始；
- 尚未执行过查询时显示 `完成:0/0　耗时:0h:0m:0s`。

最终批次汇总写入 `sessionStorage`，页面刷新后仍能恢复；下一批查询开始时覆盖旧汇总。

## 手机端副标题

在不超过 720px 的工作页面上隐藏页面主标题下方的 `p` 或 `.app-subtitle`。英文眉题 “BARCODE OPERATIONS CENTER” 和主标题继续显示；登录页和无权限页的正文说明不受影响。

## 验收标准

- 430px 宽度下查询通道不再横向溢出，标题右侧显示选择数量。
- 下拉层可以全选、单选和恢复默认全选，并显示 10 个通道状态。
- 721px 及以上仍显示原有通道按钮。
- 实时队列标题在桌面端和手机端都显示完成数量及 `h:m:s` 耗时。
- 查询结束后刷新页面，最近批次汇总仍在；开始下一批后重置。
- 手机端查询、结果、移库、匹配、设置页面不显示主标题副标题，桌面端仍显示。
- 现有前端契约测试和路由测试全部通过，手机视口无页面级横向滚动。
