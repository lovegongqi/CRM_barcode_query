# GYJ 已保存明细展示

## 目标

在 `/inbound` 的 GYJ 采购入库工作区中，保存成功后让右侧“保存结果”展示实际写入的物料明细，而非只显示单据号。

## 数据流

1. CRM 装箱单会先被转换为 GYJ 入库行：产品编码、名称、数量与条码列表。
2. GYJ 保存任务成功后，将这些已写入行作为 `result.products` 随 `/api/inbound/gyj/status` 返回；仍保留 `packing_slip_no` 和 `order_no`。
3. 页面仅在任务成功完成时渲染保存结果，显示装箱单号、GYJ 单据号和逐行物料明细。

## 页面行为

- 左侧“GYJ 实时日志”继续只显示操作日志，不混入物料明细。
- 右侧“保存结果”每行显示产品编码、名称和数量。
- 有条码的行提供“展开条码 / 收起条码”按钮；默认收起。
- 展开后显示该行已填入 GYJ 的全部条码；无条码配件明确显示“无条码”。
- 不新增保存、审核或编辑动作；仅展示本次已保存任务的结果。

## 验收

- 成功状态 API 含 `result.products`，每项含 `product_code`、`description`、`quantity`、`serials` 和 `record_type`。
- 保存结果可展示多行物料并默认隐藏条码。
- 每行条码可独立展开/收起。
- 失败或进行中的任务仍显示原有状态文字与操作日志。
