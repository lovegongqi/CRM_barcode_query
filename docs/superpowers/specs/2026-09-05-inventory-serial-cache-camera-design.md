# 库存序列号缓存与手机连续扫码设计

## 目标

修复序列号核对时 GYJ 查询结果偶发为空、重复刷新覆盖已加载数据和刷新失败阻断扫码的问题；增加手机端后置相机连续扫码；让分次数量审计记录明确标识具体的“第 N 笔”。

## 已确认的问题

- GYJ 序列号查询点击“查询”后只固定等待约 300 毫秒，读取逻辑可能在新结果尚未稳定时采集临时空表或旧表。
- 同一商品的审计记录显示账面序列号集合曾在 `0` 条和 `5` 条之间反复切换，证明空结果不是稳定的库存变化。
- 打开核对窗口、窗口定时器、扫码完成后的界面刷新以及完成商品核对都会再次触发或可能触发 GYJ 查询。
- GYJ 偶发读取失败会覆盖扫码成功提示；完成核对时的强制刷新还会阻止商品完成。
- 审计数据保存了分次盘点记录的 `entry_id`，但审计查询结果没有返回稳定的笔次编号。
- 手机连续调用摄像头依赖安全上下文；通过普通 HTTP 访问群晖服务时不能使用 `getUserMedia()`。

## 数据与刷新规则

每个商品第一次打开序列号核对窗口时：

- 如果从未成功同步账面序列号，则访问 GYJ 并保存结果。
- 如果已经成功同步过，则直接读取数据库中的账面序列号缓存，不访问 GYJ。
- 零条序列号也是合法的成功结果，但只有在 GYJ 查询结果稳定后才能写入缓存。

核对窗口增加“重新获取”按钮：

- 仅用户主动点击时强制访问 GYJ。
- 成功后原子替换账面序列号集合并重新分类已有扫描记录。
- 失败时保留上一次成功缓存和全部扫描记录，不用空集合覆盖，并显示错误。
- 窗口显示最近一次成功获取时间。

取消以下自动 GYJ 查询：

- 窗口打开时对已有缓存的重复查询。
- 窗口内每 60 秒刷新。
- 每次扫码后的 GYJ 库存刷新。
- 点击“完成该商品核对”时的强制刷新。

扫码、删除误扫和完成核对都使用当前缓存。扫描到缓存账面集合中的序列号时立即记为匹配；不在集合中时立即记为实物独有，不再为每个未匹配序列号同步访问 GYJ。这样连续扫码完全不依赖 GYJ 在线状态。主动重新获取账面集合后，系统按新集合重新分类已有扫描记录；历史中已经识别出的“其他商品/已出库”资料继续保留。

## GYJ 查询稳定性

序列号报表查询不再依赖单次固定延时。点击查询后循环读取表格状态，直到满足以下条件：

- 加载状态已结束；
- 表头和分页总数可解析；
- 当前结果与查询字段一致；
- 结果在连续多次采样中保持一致。

在限定时间内不能稳定则报错，不写入新缓存。非空旧缓存永远不会被一次超时或异常读取清空。

## 手机连续扫码

核对窗口增加“相机连续扫码”和“停止相机”控制及视频预览区。

- 使用项目内固定版本的 ZXing 浏览器库，避免依赖浏览器实验性的原生 `BarcodeDetector`。
- 默认请求后置摄像头，连续识别一维和二维条码。
- 识别结果进入现有串行扫码队列，沿用相同的保存、分类和审计接口。
- 对镜头中持续出现的同一码做短时间去重，后端仍保留最终重复检测。
- 每次保存结束后继续识别下一条，不关闭相机。
- 每条扫码只与本地账面缓存比对，不发起 GYJ 页面查询。
- 关闭核对窗口、切换商品、页面隐藏或点击停止时立即释放摄像头。
- 摄像头权限拒绝、设备无摄像头或页面不是 HTTPS 时，给出明确提示，手持扫码枪和键盘输入仍可继续使用。

群晖部署需要通过 HTTPS 反向代理访问该应用。应用本身不绕过浏览器安全限制，也不在普通 HTTP 页面伪装相机可用。

## 分次数量审计编号

审计接口解析 `entry_id`，按同一任务、同一商品首次出现的新增事件建立稳定笔次：第 1 笔、第 2 笔，以后不因删除而重排。

弹窗标题显示为：

- `新增第 1 笔数量`
- `修改第 1 笔数量`
- `删除第 1 笔数量`

遗留审计记录如果缺少有效 `entry_id`，继续显示原事件名称，不伪造编号。

## 影响范围

- `gyj_inventory.py`：等待稳定的序列号查询结果。
- `inventory_service.py`：缓存优先、手动强制刷新和使用缓存完成核对。
- `inventory_store.py`：输出稳定笔次编号。
- `templates/inventory.html`、`static/inventory.js`、`static/inventory.css`：手动刷新、最近同步时间、相机预览和连续扫码、审计编号。
- `static/vendor/`：固定版本的 ZXing 浏览器产物及许可证。
- 现有库存、序列号和前端测试：覆盖缓存、空结果保护、无自动刷新、相机生命周期和笔次编号。

## 验收标准

- 已有成功缓存时反复打开窗口不会访问 GYJ。
- 扫码和完成商品核对不因后台刷新失败被阻断。
- 连续扫描未匹配序列号时也能立即保存为实物独有，不等待 GYJ。
- 主动重新获取失败后仍显示上一次账面序列号和扫描结果。
- GYJ 查询中的临时空表不会被保存为零条库存。
- HTTPS 手机页面能开启后置相机并连续提交多个不同序列号，关闭窗口后摄像头指示立即熄灭。
- HTTP 页面明确说明需要 HTTPS，且不影响手持扫码枪或键盘输入。
- 修改记录能明确显示每条事件对应第几笔数量。
- 全量自动化测试通过。
