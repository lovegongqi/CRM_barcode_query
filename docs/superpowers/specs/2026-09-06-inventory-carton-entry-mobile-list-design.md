# 库存盘点整箱序列号录入与手机列表优化设计

## 目标

在现有库存盘点和序列号核对流程中增加按箱快捷录入能力：盘点人员可以长期保存每个商品的箱规，扫描箱内第一根序列号，检查其是否属于当前商品的账面序列号，编辑连续生成的条码预览后一次性写入。已保存的箱以内部批次分组，外部用实际条码范围标识，支持展开明细、单条补录、单条删除和整箱删除。

同时增加当前盘点商品的产品类别筛选，并将手机端商品列表改为默认紧凑、按需展开，使一屏可以查看多个商品。

## 已确认规则

- 采用正式保存箱组数据的方案，不使用仅存在于浏览器的临时分组。
- 不记录或展示业务箱号；箱组只使用数据库内部 ID 关联。
- 箱内序列号通常连续，但扫描结果可能误扫，因此起始序列号必须先进入可编辑输入框，并在生成后与当前商品的账面缓存立即比对。
- 连续生成只递增序列号末尾连续数字，保留其余前缀和前导零。
- 序列号末尾没有数字时不允许自动生成，只能逐条添加。
- 不同商品的每箱数量不同；任何盘点人员都可以设置并长期保存商品箱规。
- 已保存箱组外层显示实际序列号范围，展开显示条码明细。
- 箱内条码可单独添加、删除；整箱可一次删除。
- 手机端商品卡默认紧凑，点击展开后显示完整资料和全部操作。
- 产品类别筛选用于当前盘点商品列表，不用于箱内序列号明细。

## 用户流程

### 设置商品箱规

序列号核对窗口显示当前商品的每箱数量。

- 已有箱规时直接显示并用于生成。
- 未设置时，盘点人员填写正整数后保存。
- 任何盘点人员均可修改，修改后长期供后续盘点任务使用。
- 每次修改记录原数量、新数量、操作人和时间。
- 箱规建议限制为 `1–999`；空值、零、负数、小数和超出范围的值不能保存。

箱规修改只影响以后生成的新箱，不重算已经保存的箱组。

### 整箱录入

在序列号核对窗口增加“整箱录入”区域：

1. 点击“扫描起始序列号”，扫码枪、键盘或手机相机单次捕获箱内第一根序列号，写入可编辑输入框。
2. 用户可修正误扫内容。
3. 点击“生成本箱条码”，系统按当前箱规生成预览，不立即保存。
4. 系统立即把预览中的每条序列号与当前商品已成功缓存的账面序列号比对；不在本商品账面的条码逐条标红并显示汇总警告。若没有成功缓存，禁止生成或保存并提示先“重新获取”。
5. 预览显示箱规、条码范围和总条数；每条序列号可修改、删除，也可手工新增。手工增删后重新比对，最终条数可以与箱规不同，界面需明确提示“箱规 N，实际录入 M”。
6. 账面不匹配可能是真实盘盈，因此不直接阻止保存；存在不匹配项时，“确认整箱录入”必须再弹出一次明确确认。服务端随后重新校验并在单个数据库事务中写入内部箱组和全部序列号。

生成算法保留起始序列号末尾数字的最小位宽。例如箱规为 3 时，`REG202609160521` 生成 `REG202609160521`、`REG202609160522`、`REG202609160523`。数字递增发生进位时允许结果自然增加位数。

### 已保存箱组

已保存箱组默认折叠，外层显示：

- 实际条码范围：连续纯数字尾号使用共享前缀压缩显示，例如 `1422608126281～6300（20条）`；
- 经手工增删后不连续时显示首末条码、实际条数和“含不连续条码”；
- 当前有效条码数量；
- 创建人和创建时间；
- 展开与整箱删除操作。

展开后列出条码明细及分类结果。每条条码可以单独删除；箱组内提供补录输入框，新增条码仍归属当前箱组。整箱删除需要二次确认，并一次停用该箱当前有效的全部条码。

历史逐条扫描且没有箱组的数据继续显示为“未分箱条码”，不做自动迁移。

### 序列号列表紧凑显示

- “匹配、账面独有、实物独有、其他商品、重复扫描、箱组、未分箱条码”等所有条码分组默认折叠，只显示分组名称、数量和展开按钮；需要时点击展开明细。
- 当前窗口刷新或多设备轮询更新数据时保留用户已经展开的分组状态，关闭序列号核对窗口后重置为默认折叠。
- 实扫序列号按扫描时间倒序显示，最新扫描的条码始终位于对应列表最上方，便于立即核对。
- 当前商品的匹配记录不重复显示商品条码和商品名称；只有“其他商品”“已出库”等异常分类保留识别问题所需的补充信息。
- “删除误扫”放在序列号同一行右侧，使用紧凑按钮，不单独占据一行。
- 箱组展开后的条码明细和“未分箱条码”采用相同的紧凑行规则。

## 数据模型

### 商品箱规

新增商品箱规表，以商品条码作为稳定业务键，保存：

- 商品条码；
- 每箱数量；
- 创建时间；
- 更新时间；
- 最后修改人。

箱规是本系统所有盘点人员共享的长期配置，不按任务或设备隔离。并发修改采用最后成功提交值；每次成功修改均写审计记录，因此可以追溯覆盖顺序。

### 盘点箱组

新增盘点箱组表，保存：

- 箱组 ID；
- 盘点任务 ID；
- 商品条码；
- 创建时采用的箱规；
- 确认保存时的实际有效条码数量；
- 起始序列号；
- 创建人、创建时间；
- 是否有效、删除人和删除时间。

箱组 ID 只用于内部关联和并发校验，不作为业务箱号展示或接受用户输入。

### 箱内序列号关联

现有实扫序列号记录增加可空的箱组 ID：

- 整箱确认及箱内补录写入对应箱组 ID；
- 普通逐条扫描保持为空；
- 单条删除沿用现有停用逻辑，不物理删除；
- 整箱删除批量停用该箱全部有效扫描记录；
- 箱组和扫描记录的审计历史永久保留。

任务内序列号仍保持唯一。数据库唯一约束是多设备并发提交的最终保护，前端预检只用于提前提示。

## 服务与接口

新增最小接口集合：

- 读取当前商品箱规；
- 保存或修改商品箱规；
- 预检并创建整箱；
- 向指定箱组补录单条序列号；
- 删除箱组中的单条序列号；
- 删除整个箱组。

整箱创建请求只提交箱规快照、起始序列号和用户确认后的完整序列号数组。服务端不能信任浏览器生成结果，必须重新验证：

- 当前任务和商品仍允许核对；
- 已有成功的账面序列号缓存；
- 箱规和序列号格式有效；
- 请求数组非空、数量不超过安全上限，并且没有空值或内部重复；
- 序列号在任务内不存在有效扫描记录。

验证通过后，在一个事务中创建箱组并写入全部扫描记录。任一条失败则整箱不写入。

每条序列号只与现有 GYJ 账面缓存分类：在账面集合中记为匹配，否则沿用现有未知/实物独有分类。整箱生成、确认、单条补录、单条删除和整箱删除均不得访问 GYJ；只有现有“重新获取”按钮可以强制访问 GYJ。

接口返回更新后的完整序列号核对视图，包括箱组、未分箱扫描和汇总，使现有多设备轮询可以合并显示同一状态。

## 审计记录

新增审计事件：

- 设置或修改商品箱规；
- 整箱录入；
- 箱内补录序列号；
- 箱内删除序列号；
- 整箱删除。

整箱事件保存箱组 ID、条码范围、影响条数和序列号列表。单条事件保存箱组 ID、序列号、原分类、操作人和时间。审计详情仅返回界面需要的白名单字段，不暴露数据库内部信息。

## 产品类别筛选

当前盘点工具栏新增“产品类别”选择框：

- 默认“全部类别”；
- 选项从当前任务全部商品的 `category` 字段去重、排序生成；
- 与文本搜索和现有“查看范围”筛选同时生效；
- 只影响商品列表显示，不改变顶部任务汇总数字；
- 轮询更新商品后重新生成选项，如果当前选择仍存在则保留，否则回到“全部类别”；
- 不把筛选状态写入服务器，也不影响其他设备。

## 手机端紧凑商品卡

在 `720px` 以下，商品卡默认使用紧凑布局：

- 第一行显示商品条码、名称和当前状态；
- 第二行紧凑显示账面、实盘和差异；
- 保留当前阶段最重要的主操作，例如“盘点数量”或“核对序列号”；
- 规格、型号、类别、单位、分次记录提示和次要操作默认折叠；
- 点击展开后显示现有完整资料和全部操作，再次点击收起；
- 默认紧凑高度目标约 100 像素，使常见手机一屏能看到约 3–4 个商品；
- 桌面端保持完整卡片布局。

展开状态只保存在当前浏览器内。轮询刷新不能无故收起用户正在查看的卡片；商品离开当前筛选结果时可以移除其本地展开状态。

## 手机相机行为

现有“相机连续扫码”继续用于普通逐条序列号扫描。

整箱表单中的起始序列号使用单次捕获模式：

- 用户先明确选择要扫描的字段；
- 相机成功识别一个值后停止并释放摄像头；
- 识别值只写入输入框，不生成、不保存；
- 用户编辑并点击“生成本箱条码”后才进入预览；
- HTTPS、安全上下文、后置相机和错误提示规则沿用现有相机控制器。

## 错误处理与并发

- 扫到附近错误条码不会自动入库，所有扫描字段都可编辑。
- 预览和服务端分别校验；服务端结果是最终依据。
- 任一序列号被另一设备抢先保存时，整箱事务回滚并显示具体冲突项。
- 删除已经被其他设备删除的单条或箱组时返回可理解的“记录已变化，请刷新”提示。
- 箱规并发修改采用最后成功提交值，并在审计记录中显示修改顺序。
- 所有错误提示使用固定、可操作的中文信息，不显示 SQL、异常栈或 GYJ 内部错误。

## 影响范围

- `inventory_store.py`：箱规、箱组、序列号关联、事务与审计。
- `inventory_service.py`：输入验证、连续序列号生成、缓存分类和并发错误。
- `app.py`：箱规与箱组接口。
- `templates/inventory.html`：类别筛选、整箱表单与箱组区域。
- `static/inventory.js`：预览、批量提交、分组渲染、单次相机捕获、类别组合筛选和手机卡展开状态。
- `static/inventory.css`：手机紧凑卡、箱组与预览布局。
- 库存 store/service/API/frontend/contract 测试。

## 验收标准

- GAC 等商品可各自保存不同箱规，普通盘点人员可以修改并长期复用。
- 扫描起始序列号后可先修改，再生成连续预览；生成保留前缀和前导零。
- 预览立即与当前商品账面缓存比对；不匹配条码醒目标记，保存前二次确认。
- 预览可逐条修改、删除和添加；确认前不写入盘点数据。
- 预览经手工增删后允许实际条数与箱规不同，并在保存前清楚显示两者差异。
- 整箱确认具备原子性，任一重复序列号不会留下半箱数据。
- 已保存箱按条码范围折叠显示，展开可查看明细、补录、单条删除；整箱删除需要确认。
- 实扫序列号按最新扫描优先显示，正常匹配行不重复商品资料，删除按钮与序列号保持同一行。
- 所有条码分组默认折叠，按需展开，并在窗口保持打开时保留展开状态。
- 整箱和单条操作均可在修改记录中追溯操作人、时间和影响内容。
- 所有箱组和汇总通过现有轮询在多设备间同步，整箱操作不访问 GYJ。
- 产品类别筛选可与搜索和查看范围组合，并且不改变任务汇总。
- 手机商品卡默认紧凑，一屏可查看多个商品；展开后原有信息和操作完整可用。
- 手机整箱扫码采用单次捕获，识别后释放相机且只填入可编辑字段。
- 全量自动化测试通过。
