# 独立安卓客户端设计

## 目标与边界

交付可安装的 Android APK。安装后，查询、结果、移库、入库、盘点、匹配、结单管理和设置页面及其现有单机操作都在手机上运行；CRM 与 GYJ 操作可使用网络，但运行时不访问本项目的 NAS 服务。首次安装从空白数据开始，条码结果、配置、任务和历史只保存在该手机。用户明确接受取消跨手机共享历史与多人协同盘点。

“独立”指 APK 包含自身的界面、业务进程和持久化数据，不以 NAS 网页或 NAS API 为后端。CRM／GYJ 本身仍是在线外部系统：断网时本机历史可查看，远端查询和写入不可完成。不能把远端操作的失败显示为本地成功。

## 现状与约束

当前应用是 Flask + Playwright：`app.py` 有 141 个路由，CRM 与 GYJ 工作流依赖桌面 Chromium。[Playwright Python 的官方运行系统要求](https://playwright.dev/python/docs/intro#system-requirements)不包含 Android；其 [Android 自动化接口](https://playwright.dev/docs/api/class-android)要求外部 ADB，不能直接作为 APK 内的浏览器运行时。因此现有桌面包无法直接转换为满足上述目标的安卓包。

CRM 配置目前指向 HTTP 门户，GYJ 使用 HTTPS。安卓客户端只允许连接明确配置的 CRM／GYJ 主机；先验证 CRM 是否支持 HTTPS，若不支持，单独记录明文传输风险和对应的窄范围网络配置，不开启全局明文访问。APK 不内置账号、密码、Cookie 或 NAS 数据。

## 方案

采用原有移动版网页界面加安卓宿主的混合结构。APK 内置页面与静态资源，WebView 只访问应用本机回环地址和经允许的 CRM／GYJ 页面。宿主启动仅绑定本机回环地址的 Flask 业务进程，将数据目录映射到应用私有存储，以便尽量沿用现有页面、路由、校验和导出逻辑。Python 运行环境拟采用 [Chaquopy](https://chaquo.com/chaquopy/doc/current/android.html)，但是否能运行当前 Flask 与导出依赖必须先在 Android 构建和设备上实证；不能仅依据桌面测试认为可用。

Playwright 工作流由 `CrmPortalAdapter`、`GyjPortalAdapter` 两个手机端实现替代。优先使用经抓包和业务响应验证的 CRM／GYJ HTTP 接口；需要页面交互的登录、验证码、老式报表和表单流程使用安卓 WebView，并与本机业务进程同步会话。只在手机端替换门户适配层，不改变桌面和 NAS 的现有运行时。每个操作保留现有输入校验、预览／确认边界、执行状态和事后重读核验；HTTP 200 不代表业务成功。

本机使用现有 SQLite／文件格式的可移植部分保存结果、产品前缀库、入库历史、盘点任务、结单记录和设置。账号数据与会话仅保存在应用私有空间；需要持久保存的密码通过安卓安全存储保护。导出文件经安卓系统文件选择器保存。移库、入库、型号修正、结单确认等远端写入在手机端继续使用现有确认流程，不自动执行生产数据写入。

手机端盘点锁只在本机生效，页面不显示其他手机的在线状态。设置页仍提供本机账号、主题和通道配置；通道并发上限根据手机资源测定，但不删除批量操作能力。

## 交付顺序与验收

1. **运行时可行性**：在 Android 模拟器或真机上启动内置页面、Flask、本机持久化和导出；关闭 NAS 后仍可打开全部页面与本机历史。验证 CRM、GYJ 的登录、会话恢复、一个只读查询和必要的老式页面交互。任一关键验证失败时暂停功能迁移，带着失败证据重新评审运行时方案，不发布伪装为独立版的 APK。
2. **功能迁移**：按查询／结果、匹配、移库、入库、盘点、结单、设置逐项替换 Playwright 依赖，保留现有单机行为和错误提示。每个远端写入都有可审核的请求预览、业务响应检查和重读验证。
3. **发布验证**：在不连接 NAS 的测试网络中完成各页功能检查；覆盖进程重启后的数据持久化、网络中断与恢复、账号隔离、导入／导出、验证码、长任务后台限制以及不同屏幕尺寸。对远端写入只用专用测试单据验证。构建签名 APK，核验安装、启动、版本和 SHA-256，再上传 GitHub Release。

第一版发布标准是上述八个页面及其现有单机操作均通过设备验证；不能以一个仅能打开页面的 WebView 壳作为完成。由于 CRM／GYJ 接口并非本项目控制，门户变更可能要求后续更新适配层。
