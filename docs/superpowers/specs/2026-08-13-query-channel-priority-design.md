# 查询通道协作式优先级调度

## 目标

将普通 CRM 条码批量查询设为最低优先级，让匹配页在线查询、结果页结单确认和入库页装箱单读取在查询通道可用时优先执行。

## 选择的方案

采用协作式优先级调度和共享高优先级等待队列：不取消正在执行的单个 CRM 操作；当没有空闲通道时，入库、结单和匹配任务先创建为等待中的任务。普通批量查询在每条条码完成后、领取下一条之前检查该队列并让出通道。

不采用中断式抢占：强制停止当前浏览器查询可能留下未完成页面状态或丢失查询结果。

## 优先级

1. 入库页装箱单读取
2. 结果页结单确认
3. 匹配页在线查询
4. 查询页普通条码批量查询

同一优先级内保持现有先到先执行的行为；不会改变单个已开始任务的执行顺序。

## 调度边界

- 高优先级任务启动时无空闲通道不再直接失败，而是进入共享等待队列并向页面返回任务 ID 和“等待查询通道”状态。
- 调度器为等待队列的首个任务分配最先释放的查询通道，并沿用现有的占用登记，保证一个通道始终只由一个 CRM 操作使用。
- 普通批量任务只在领取下一条码前判断是否应让出某个空闲后的通道。
- 已运行的普通条码查询完成后，若存在高优先级需求，该通道不再领取下一条普通条码，直到高优先级需求被分配或完成。
- 若没有高优先级需求，普通批量查询保持当前吞吐量。
- 任何查询通道仍只能被一个 CRM 操作占用；不并发复用浏览器页。

## 验收

- 普通批量查询运行期间启动入库、结单或匹配在线查询，接口会立即返回可轮询的等待任务；它们不会中断当前条码，但会优先获得随后释放的通道。
- 普通查询仅在没有高优先级待执行工作时领取下一条。
- 入库、结单、匹配任务现有的占槽隔离与失败处理保持有效。
- 调度逻辑有自动化测试覆盖，验证优先级和“不打断当前条码”规则。
