# GYJ 库存盘点协同录入与任务重开设计

## 背景与目标

现有盘点功能按“一个商品一次填写、第一台设备锁定、全部数量盘完后再核对序列号”的流程运行。实际盘点中，同一商品可能分散在多个地方，多名仓管员也可能从不同设备同时盘点；单次总数和商品锁都会妨碍协作，并且录错后无法直接修正。

本次调整实现以下目标：

- 同一商品可以分多次录入数量，并以 `12 + 13 = 25` 的形式展示明细与合计；不记录位置信息。
- 任意有盘点权限的设备都能新增、修改或删除任意一笔数量。
- 取消数量盘点和序列号核对的商品锁，多台设备实时合并结果。
- 已盘商品在活动任务中可以反复打开和修正。
- 数量出现序列号差异后立即开放序列号核对，不等待其他商品盘完。
- 允许只盘部分商品后完成任务；未盘商品不进入差异报告。
- 所有修改保留操作人、时间和修改前后内容。
- 管理员可以把历史任务恢复为活动任务继续盘点，但同一账号仍只能有一个活动任务。

本功能继续只读 GYJ，不向 GYJ 创建、修改或删除任何数据，也不保存或展示价格。

## 选定方案

采用独立的分次数量记录表，而不是把所有数量保存为一个 JSON 数组，也不引入完整事件溯源系统。

每次录入是一条有独立标识和版本的记录。商品实盘数量由服务端汇总其所有有效记录。这样，不同设备新增不同记录时不会相互覆盖；两个设备同时修改同一笔记录时，服务端可以只拒绝已经过期的那一次修改。

## 数据模型

### 分次数量记录

新增 `inventory_count_entries`，至少包含：

- 记录 ID；
- 盘点任务 ID；
- 商品条码；
- 数量；
- 记录版本；
- 创建人、创建时间；
- 最后修改人、最后修改时间。

不保存区域、货架或其他位置信息。商品的实盘总数、算式和差异均由有效记录实时计算，不另存一份可被覆盖的浏览器端合计。

删除采用数据库事务内的实际删除，同时把删除前的完整内容写入审计日志。页面和接口不得把已删除记录继续计入合计。

### 商品状态

`inventory_items` 继续保存商品资料、GYJ 账面数量、完成时与最新账面数量、序列号标记和当前状态。原单值实盘字段仅用于兼容迁移，不再作为新写入的权威来源。

每次分次记录变化后，服务端在同一事务内：

1. 汇总该商品的全部数量记录；
2. 读取或使用本次操作要求的最新 GYJ 账面数量；
3. 重新计算差异和商品状态；
4. 增加任务版本；
5. 写入审计事件。

商品没有任何数量记录时为“待盘点”。有记录且差异为零时为“数量一致”。无序列号商品存在差异时为“盘盈”或“盘亏”。有序列号商品存在差异时为“待序列号”。

### 兼容迁移

数据库升级时，为现有活动任务中已经填写过实盘数量的商品补建一条分次记录，数量取原实盘值，操作人标记为迁移记录，并保留原时间。既有历史任务保持可查看和导出；任务被管理员恢复时，再按同样规则补齐可编辑记录。

现有商品锁数据不再参与数量或序列号写入。迁移完成后清除活动锁；锁表暂时保留以兼容旧数据库版本，不再生成新锁或心跳。

## 多设备并发与实时同步

- 新增数量记录不要求商品锁，多台设备可以同时新增。
- 修改或删除携带该条记录的版本号。版本不一致时返回冲突和最新记录，页面刷新该商品并提示用户重新确认，不静默覆盖。
- 不同数量记录之间互不阻塞。任务版本只用于通知其他设备刷新，不作为所有写入共用的粗粒度互斥锁。
- 序列号扫描取消商品锁。数据库以“任务、商品、序列号”唯一约束去重；重复扫描返回已有结果而不是制造两条记录。
- 序列号删除和重新分类在事务中执行，并写入审计日志。多个设备看到相同的服务端合并结果。
- 客户端沿用短轮询同步任务版本，当前打开的数量或序列号窗口也在版本变化时刷新。编辑框中尚未提交的内容不被后台刷新清空。
- GYJ Worker 仍按账号串行执行浏览器读取，取消的是工具内商品编辑锁，不是对同一浏览器自动化会话的串行保护。

## 数量盘点交互

商品卡片在活动任务中始终可以重新打开，包括已经数量一致、盘盈、盘亏或待序列号的商品。

数量窗口显示：

- 商品资料；
- 最新 GYJ 账面数量；
- 分次数量记录列表；
- 每条记录的数量、创建人、创建时间、最后修改人和最后修改时间；
- 合计算式，例如 `12 + 13 = 25`；
- 合计实盘数量和实时差异；
- 新增数量、修改和删除操作。

新增、修改或删除前，服务端重新读取该商品的 GYJ 全部仓库库存总数量。GYJ 读取失败时不落盘本次修改，页面保留用户输入并明确提示重试。

数量记录变化后，如果商品仍有序列号差异，则状态回到“待序列号”，已有扫描记录保留但必须用最新 GYJ 未出库序列号重新校验后才能标记核对完成。如果差异变为零，不再要求序列号核对；已有序列号操作只保留在审计历史中。

## 即时序列号核对

任务处于数量盘点阶段时，只要商品状态为“待序列号”，商品卡片和待核对队列就立即提供“核对序列号”入口。

打开后实时读取该商品全部仓库的未出库序列号，允许多台设备同时扫描，并合并显示：

- 账实一致；
- 账上有、现场没有；
- 现场有、账上没有；
- 属于其他商品；
- GYJ 已出库；
- GYJ 查不到。

序列号窗口不再申请锁或发送心跳。完成核对前仍需再次刷新 GYJ 未出库序列号；失败时不得把该商品标记为已核对。

## 部分完成盘点

当前盘点页增加“完成盘点”按钮。点击后由服务端重新计算任务状态：

- 没有任何数量记录的商品视为未盘，不进入商品差异、序列号差异或导出报告；
- 已盘且无差异的商品保存为任务统计，但不写入差异报告；
- 已盘且有差异的商品写入差异报告；
- 已完成序列号核对的商品写入具体序列号差异；
- 仍为“待序列号”的商品先触发确认提示。

第一次提交完成请求且存在待核对序列号时，服务端返回需要二次确认，并提供待核对商品数量。页面列出警告，用户确认后以明确的 `allow_unverified_serials` 参数再次提交。完成后的这些商品以“序列号未核对”写入差异报告，不伪造具体缺失或多出序列号。

完成操作记录盘点范围、未盘商品数、未核对序列号商品数、确认人和时间。任务进入历史后普通账号不能再修改。

## 管理员继续盘点

历史任务详情中仅管理员可见“继续盘点”按钮，接口也必须验证管理员身份。

恢复规则：

- 同一工具账号存在其他活动任务时拒绝恢复，并提示先完成当前任务；
- 恢复原任务，不创建内容重复的新任务；
- 保留全部分次数量、序列号扫描、差异、备注和审计日志；
- 清除任务完成时间并回到数量盘点阶段；
- 重新读取当前 GYJ 商品库存，并按最新数据重算已盘商品状态；
- 先前由“序列号未核对”生成的差异恢复为待核对，后续再次完成时重建该任务的差异结果；
- 写入恢复人、恢复时间和恢复前后状态的审计事件。

历史列表在任务恢复后不再把它显示为已完成任务；再次完成后使用同一任务编号回到历史列表。

## 审计与修改记录

每次新增、修改和删除分次数量均记录：任务、商品、记录 ID、操作类型、修改前值、修改后值、操作账号、设备标识和时间。

序列号新增、删除、重新分类、数量重算、未核对确认、任务完成和任务恢复也写入审计事件。审计日志不可由普通盘点操作删除。

当前任务提供“修改记录”入口，可按商品查看数量与序列号变更。历史任务继续保留完整操作日志。价格和密码等敏感字段不得进入审计详情。

## 接口调整

在现有盘点接口下增加或调整以下能力：

- 获取商品详情时返回分次数量记录、算式、合计和记录版本；
- 新增一笔数量；
- 按记录 ID 修改一笔数量；
- 按记录 ID 删除一笔数量；
- 数量和序列号写入不再要求商品锁或心跳；
- 数量盘点阶段允许打开、刷新、扫描和完成待核对序列号商品；
- 完成任务支持“需要确认”和 `allow_unverified_serials`；
- 管理员恢复历史任务；
- 查询任务或商品的修改记录。

旧的单值数量提交、商品 claim 和 heartbeat 接口在前端切换后停止调用。为避免旧页面误写，可在一个兼容周期内返回明确的“请刷新页面”错误，而不是把旧写入转换成新记录。

## 错误处理

- GYJ 库存读取失败：不保存数量变化，保留输入并允许重试。
- 数量记录版本冲突：返回最新记录和商品汇总，要求重新确认。
- 数量记录已被其他设备删除：刷新列表并提示该记录已删除。
- 重复序列号：返回原记录及分类，不重复计数。
- GYJ 序列号刷新失败：保留扫描进度，但不允许完成核对。
- 存在待核对序列号：首次完成任务只返回确认要求，不改变任务状态。
- 恢复历史任务时已有活动任务：拒绝恢复且不改变任何任务。

## 测试与验收标准

### 数据与服务测试

- 两台设备同时新增不同数量记录，两笔均保存且合计正确。
- 任意设备能修改或删除另一设备创建的记录，并保留完整审计信息。
- 同一记录并发修改时，过期版本被拒绝且不覆盖新值。
- 已盘商品可重复打开和修改，状态及差异随最新合计重算。
- 分次数量以明细和 `12 + 13 = 25` 算式返回。
- 数量变化导致序列号差异时立即可核对；差异归零时不再要求核对。
- 多设备扫描同一序列号只产生一条有效记录。
- 完成序列号核对前强制刷新 GYJ，失败时保持待核对。
- 部分完成不把未盘商品写入差异报告。
- 存在待核对序列号时首次完成不改变任务，二次确认后写入“序列号未核对”。
- 普通账号不能恢复历史任务；管理员在没有其他活动任务时可以恢复。
- 有活动任务时恢复被原子拒绝。
- 既有活动任务和历史任务迁移后数据不丢失。

### 页面与接口测试

- 已盘商品卡片仍可点击，分次记录可增删改。
- 页面正确显示记录明细、操作人、时间、算式、合计和差异。
- 数量盘点阶段立即显示并打开序列号核对入口。
- 页面不再发送 claim、heartbeat 或旧单值数量提交请求。
- 其他设备写入后当前列表和已打开窗口实时刷新，未提交输入不被清空。
- 完成盘点按钮正确执行待序列号二次确认。
- “继续盘点”仅管理员可见，服务端权限不能由前端绕过。
- 修改记录完整显示数量与序列号的操作人、时间和前后值。

### 回归与安全

- 现有 GYJ 登录、验证码、商品库存、序列号统计和 60 秒库存同步继续工作。
- 页面、接口、SQLite、日志和导出均不包含任何价格或金额字段。
- 本功能不执行任何 GYJ 写操作。
- 项目重启、页面刷新和设备断网重连后数据与审计记录可恢复。
