# 批量结单状态恢复与服务单号排序设计

## 目标

切换到其他页面再返回结果页时，恢复同一浏览器标签内的批量结单任务状态；同时让使用同一最新服务单号的条码连续显示。

## 批量结单状态恢复

开始批量结单并收到服务端响应后，结果页将任务 ID、通道 ID 和开始时间写入 `sessionStorage`。这些数据只保留在当前浏览器标签的会话中，不会在账号之间共享。

结果页初始化时读取该任务信息，并调用既有的 `/api/service-close/status` 接口。恢复时从服务端保留日志的开头重新读取，确保离开页面前后的日志都能显示。若任务仍在运行，页面恢复“结单中”按钮状态、日志、进度轮询和开始时间；若任务已完成，页面应用返回的结单结果和失败明细、刷新条码数据并显示最终提示，然后清除已保存的任务信息，避免后续每次返回页面都重复展示已完成任务。

读取状态失败时保留已保存任务信息，并在下一次轮询或重新进入结果页时继续尝试；不会创建新任务，也不会影响后端已在运行的结单任务。

## 安装服务单筛选与排序

所有“最新服务单号”取值都只考虑服务类型 `typestr1` 含“安装”的服务单。维修、保养及其它非安装服务单不参与结果页卡片显示、条码分组排序或批量结单选单；如果一个条码没有安装服务单，则批量结单将它归为无可结单服务单。

结果页从筛选后的安装服务单中取最新服务单号作为排序键。非空服务单号按自然字符串顺序排序，因此同一服务单号的条码连续显示；没有安装服务单号的条码统一排在末尾。

同一服务单号组内保留现有优先级：包含已结单服务单的多服务单条码优先，其余按查询时间倒序。条码拥有多个安装服务单号时仅按卡片当前显示的最新安装服务单号分组，避免一张卡片同时出现在多个组内。

## 验收条件

1. 批量结单启动后切换到查询页并返回结果页，能重新显示同一任务的进度和新增日志，并持续轮询直至结束。
2. 任务在离开结果页期间结束时，返回结果页能展示最终结单结果与失败明细，随后不再在以后的页面访问中重复恢复该已完成任务。
3. 相同最新安装服务单号的条码在结果列表中相邻；无安装服务单条码排在所有有安装服务单条码之后。
4. 维修和保养服务单不会成为卡片显示、排序或批量结单的服务单号。
5. 现有筛选和批量结单提交流程保持不变。
