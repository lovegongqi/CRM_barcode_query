# GYJ 后台登录设计

## 目标

将 GYJ 采购入库的登录方式改为与 CRM 查询通道一致：用户在工具页面输入 GYJ 账号和密码，由后台 GYJ 浏览器会话完成登录，并在后续采购入库任务中复用该会话。不再打开独立的 GYJ 登录窗口。

## 页面

`/inbound` 的 `GYJ采购入库` 工作页增加：

- GYJ 账号和密码输入框；
- `记住账号密码` 复选框；
- `后台登录 GYJ` 按钮及登录状态；
- 当 GYJ 登录页出现验证码时，显示验证码输入框和提交按钮。

登录成功后，现有 `创建并保存` 操作保持不变。页面只显示账号（若选择记住）和密码占位符；不回显密码。

## 凭据和会话

- 凭据按工具账号 ID 隔离，沿用 CRM 的配置目录和 JSON 存储方式；仅在用户勾选 `记住账号密码` 时保存。
- 未勾选时，账号和密码仅用于当前登录请求，不写入磁盘、日志或任务状态。
- 后台 GYJ 会话使用专用、按工具账号隔离的 Playwright 持久化目录，登录成功后可跨当前应用重启恢复并重新校验。
- GYJ 账号、密码、验证码、Cookie 和会话内容绝不包含在 API 响应、日志、Excel 或前端存储中。

## 后台登录流程

1. 页面提交账号、密码和是否记住。
2. 后端校验非空；若要求记住则更新该工具账号的 GYJ 凭据记录。
3. GYJ Worker 打开登录页、填写账号和密码并点击普通登录按钮。
4. 若立即跳转离开登录页，任务标记为已登录；若出现验证码，登录状态标记为 `waiting_captcha`，前端显示验证码输入。
5. 前端提交验证码后，Worker 只在已有登录页填写验证码并确认；成功后继续复用同一会话。
6. GYJ 入库任务开始前重新检查该后台会话。登录失效时拒绝新建单据，并提示重新后台登录。

## 接口

受 `inbound` 权限保护，新增或替换为：

- `GET|POST /api/inbound/gyj/credentials`：读取记住标志和账号；保存或清除当前工具账号的 GYJ 凭据。
- `POST /api/inbound/gyj/login`：接收账号、密码，启动后台登录。
- `POST /api/inbound/gyj/login/captcha`：提交当前账号处于等待状态的验证码。
- `GET /api/inbound/gyj/login-status`：返回是否登录、是否等待验证码和安全的状态消息。

原有 `POST /api/inbound/gyj/start` 和状态接口保持来源结果、保存限制和账号隔离。

## 安全与验收

- 不再调用 `page.goto` 打开可供人工操作的 GYJ 登录窗口；所有 GYJ 登录动作由后台 Worker 完成。
- 没有凭据、验证码无效、登录页无法确认或会话失效时，不启动采购入库保存。
- 自动保存仍只点击普通 `保存`，绝不审核、提交或处理既有单据。
- 每个工具账号只能查看自己的凭据元数据、登录状态和 GYJ 入库任务。
